# Goal v3 — injection subprocess race against reference D (the fact-identifying method)

PART 1 — GOAL + BAR
Phase 1 (done) delivered the hook + retrieval subprocess **A** (fully agentic: ~16 LLM rounds, 49–356 s). Phase 2 added **B** (deterministic multi-query prefetch + optional single LLM selection round → B:single / B:none) and **C** (deterministic grep fan-out, one file per grep, vector ramification, parallel one-round worker swarm, deterministic numbered merge). All three race methods now meet the speed bar (12/12 < 10 s).

**METHOD D — the completeness reference (NEW, replaces A as reference).** The lazy reference is disqualified: a reference must be the THOROUGH method — the one used to identify the facts. D = a corpus-grounded fact-identifying research subprocess:
- Full raw file tools (read/grep/find/ls/bash) on the corpus; **no RAG tools** (D defines what is IN the corpus, not what any pipeline retrieves — using RAG would be circular).
- Unlimited queries, unlimited rounds, no tool budget, no time budget (only a 3600 s anti-hang cap; record wall time).
- Mission per question: answer completely AND list every supporting fact as {statement, file, line} — covering every sub-ask, every relevant example/script file, every related API section.
- Run ONE-SHOT per question (cached like A was — never re-run), same model as the other baselines.
- D's listed facts are independently verified against the cited file:line by a critic (the same verification the original 50-fact grid received). Final grading grid = UNION (original verified grid ∪ D's verified facts); corpus-defect facts (e.g. the FKN Table 3.1 PDF column-bleed) are annotated and excluded from the denominator.
- D's published numbers: per-question wall time + input/output tokens, and D's own grid coverage (if D misses grid facts, that is reported as a reference-quality gap, not hidden).

BAR (race methods A, B:single, B:none, C): **speed** — complete in < 10 s wall (30 s acceptable). **Completeness** — ≥ D's grid coverage (fraction of grid facts present in the injected payload / answer), with **≤ 5% false positives** (injected sections that do not answer the question). Payload may be EMPTY when nothing is found; the empty edge must not stall. Test suite: the 12 questions (5 simple, 5 complex, 2 unrelated controls), simple→complex. **STOP RULE**: stop improving a subprocess after 3 consecutive unsuccessful speed attempts (not quicker, or loss of > 5% content). **FINAL SELECTION**: among bar-met subprocesses, the most deterministic with the fewest tokens. A is no longer the reference — it competes under the same bar (its 38/50 becomes "A vs grid").

Pieces: (1) the 12-question suite + original verified grid [done]; (2) D reference: runner + 12 one-shot cached D runs + critic verification of D's facts → final union grid + D numbers (wall, tokens, own coverage) [done — P2-R13: union grid FROZEN, 741 facts]; (3) re-judge A / B:single / B:none / C blind against the final grid (coverage, FPR%, speed, tokens, determinism) on the latest measured payloads; (4) targeted improvement rounds per subprocess as the new grid exposes gaps (speed bar must stay 12/12 < 10 s); (5) final selection + production wiring (config ragSubprocess) + verdict.md [DECISION 10/16 — DEFERRED: user verdict "coverage too low, no-go for now": no fast branch accepted (best = EF 10.7% vs A 24.6%); production STAYS A; EF parked as best fast branch; see tests/ab2/verdict.md].

PART 3 — THE LOOP
Same gauntlet: builder + harsh critic with fresh context per piece; critic inspects actual outputs, blind-scores against D's grid and the numeric bars, names the single biggest gap; loop until the bar is met or the stop rule fires. Measure on the full suite every round. PROGRESS.md is the live page.
